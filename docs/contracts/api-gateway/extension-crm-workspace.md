# Extension CRM Workspace BFF Contract

> `crm-service` 的服务职责、核心对象、owner 边界与长期命名以 [crm-service.md](../../architecture/services/crm-service.md) 为唯一稳定真相源。`auth-service`、`permission-service`、navigation、access summary 与 terminal access 边界分别以对应服务真相源和 [extension-auth-bff-login.md](./extension-auth-bff-login.md) 为准。本文只描述 browser-extension terminal 下 CRM Sales Workspace 的 API Gateway / BFF 黑盒 HTTP 契约。

## 1. Purpose

本文定义浏览器插件 CRM Sales Workspace P1 的 BFF contract。

目标：

- 让 browser extension 在用户显式启用 CRM workspace 后，完成当前网页识别、CRM 状态回显、查重、创建 Draft Lead、创建 Active Lead、Claim 公海 Lead 与打开 OES 详情的最小闭环。
- 保持 browser extension 是浏览器端入口，不拥有 CRM 业务真相。
- 保持所有 CRM 业务规则进入 `crm-service` application use case。
- 保持页面识别结论、重复判断、owner / Pool / restricted 状态与 allowed actions 由 OES 后端返回，插件前端不自行推导。

## 2. Endpoint Prefix

Extension CRM endpoints use a terminal-specific capability prefix:

```http
/extension/crm/*
```

Rules:

- Requests require an authenticated `BROWSER_EXTENSION` session.
- BFF must not trust a client-supplied terminal field.
- BFF must build downstream tenant / operator / trace / audit context from the authenticated extension session.
- BFF must not persist CRM business truth.
- BFF may compose CRM BFF view models and sanitize browser page signals before calling downstream CRM paths.
- Front end must not call `/extension/crm/*` while the local `extension.crm.workspace.enabled` preference is disabled.

## 3. Workspace Visibility And Local Enablement

Back-end visibility and user local enablement are separate.

- `navigation.visibleEntries` controls whether `extension.crm.workspace` is available to the current operator.
- `/extension/auth/session/access-summary` controls action availability through `actionCodes`.
- User local workspace preference controls whether CRM workspace actively runs in the extension.

Rules:

- If `extension.crm.workspace` is not visible, the extension must not expose CRM workspace or call this contract.
- If CRM workspace is locally disabled, the extension must not call this contract, inject CRM page scripts, or show CRM page markers.
- Local enablement does not grant permissions. Every endpoint still enforces normal BFF permission checks.

## 4. Action Codes

P1 consumes existing CRM permission codes.

| Action code | Use in extension CRM P1 |
| --- | --- |
| `crm.account.read` | Resolve page status, read CRM account detail, view low-sensitivity status. |
| `crm.account.create` | Create Draft Lead and Active Lead. |
| `crm.account.claim` | Claim ownerless Pool Lead. |
| `crm.duplicate.viewRestricted` | Allow less-redacted duplicate hints where CRM policy permits. |

Deferred in plugin P1:

- `crm.account.convert`
- `crm.account.manage`
- `crm.contact.manage`
- `crm.source.manage`
- `crm.activity.create`
- `crm.opportunity.manage`

## 5. Common Request Context

All authenticated endpoints require:

- bearer access token from `/extension/auth/*`
- current tenant context from session
- operator account context from session
- trace context from gateway request

All mutating endpoints also require audit context generated by BFF.

The browser extension may pass page signal metadata, but it must not pass tenant, operator, role, permission or terminal truth.

## 6. Core Types

### 6.1 Page Signals

`PageSignals` is browser-collected evidence. It is not CRM truth.

```json
{
  "url": "https://www.serrano-fixtures.example/about",
  "domain": "serrano-fixtures.example",
  "title": "Serrano Fixtures - About",
  "pageKind": "OFFICIAL_SITE",
  "selectedText": "Export ceramic lighting and bathroom fittings.",
  "visibleEmails": ["imports@serrano-fixtures.example"],
  "visiblePhones": ["+1 (312) 847-1928"],
  "companyNameCandidates": ["Serrano Fixtures"],
  "socialLinks": ["https://www.linkedin.com/company/serrano-fixtures"],
  "capturedAt": "2026-06-23T00:00:00.000+08:00"
}
```

Rules:

- `url`, `domain`, `title`, `pageKind`, and `capturedAt` are required for page resolve.
- `selectedText`, emails, phones, company candidates and social links are optional signals.
- BFF must normalize and bound payload size before forwarding or serializing into CRM source raw payload.
- P1 should cap `selectedText` and snippets to avoid storing large page bodies.

### 6.2 Search Result Signals

```json
{
  "searchEngine": "GOOGLE",
  "query": "ceramic bathroom fixtures importer Chicago",
  "capturedAt": "2026-06-23T00:00:00.000+08:00",
  "results": [
    {
      "url": "https://www.serrano-fixtures.example/about",
      "domain": "serrano-fixtures.example",
      "title": "Serrano Fixtures - About",
      "snippet": "Export ceramic lighting and bathroom fittings for hospitality projects."
    }
  ]
}
```

Rules:

- Search result resolve is read-only.
- Search result resolve must not create CRM records.
- P1 should cap result count to a small page-sized set.

### 6.3 Extension CRM Status

`ExtensionCrmStatus` is a BFF-facing UI status, derived from CRM facts and current authorization.

| Status | Meaning |
| --- | --- |
| `UNKNOWN` | No visible CRM record or strong duplicate was found for the current signals. |
| `POSSIBLE_DUPLICATE` | CRM found a possible duplicate that does not hard-block all actions. |
| `OWNED_LEAD` | A visible Lead exists and is owned by the current operator. |
| `POOL_LEAD` | A visible ownerless Active Lead exists and may be claimable. |
| `OTHER_OWNER_LEAD` | A Lead exists but is owned by another account; plugin receives only low-sensitivity detail. |
| `PROSPECT_CUSTOMER` | A visible Prospect Customer exists. |
| `CUSTOMER` | A visible Customer exists. |
| `RESTRICTED` | CRM detected a restricted or unauthorized existing object; plugin receives minimal status only. |

Rules:

- `UNKNOWN` may be used for current-page workspace context, where the user can still choose create or duplicate-check actions.
- Google Search Result Page annotation must not render or receive tag-bearing `UNKNOWN` records for CRM misses.

### 6.4 Allowed Actions

Allowed actions are returned per resolved page or candidate. They are not inferred by the front end.

| Action | Meaning |
| --- | --- |
| `CHECK_DUPLICATE` | User may run explicit duplicate check. |
| `CREATE_DRAFT_LEAD` | User may create a Draft Lead. |
| `CREATE_ACTIVE_LEAD` | User may create an Active Lead. |
| `CLAIM_POOL_LEAD` | User may claim a Pool Lead. |
| `OPEN_OES_DETAIL` | User may open tenant-web CRM detail. |

### 6.5 Extension-Safe CRM Account Fields

CRM account summaries exposed through this contract may include:

- `crmAccountId`
- `displayName`
- `recordStatus`
- `lifecycleStage`
- `ownerKind`
- `ownerAccountId` when not restricted
- `ownerDisplayName` when not restricted
- `leadDomain` when not restricted
- `leadEmail` when not restricted
- `createdAt`
- `lastActivityAt`
- `nextFollowUpAt`
- `archivedAt`
- `archiveReason`

Rules:

- `archiveReason` is copied from `crm-service`; API Gateway / BFF must not classify low value, invalid, non-target, competitor, no-fit, duplicate or unresponsive by itself.
- `archiveReason` is meaningful only when CRM returns `recordStatus = ARCHIVED` or `archivedAt` is present.
- Restricted records must not leak owner, contact, domain or archive reason details beyond the authorized low-sensitivity status.

## 7. Endpoint Summary

| Endpoint | Purpose |
| --- | --- |
| `POST /extension/crm/page-context/resolve` | Resolve one current page into CRM status and allowed actions. |
| `POST /extension/crm/search-results/resolve` | Resolve search result candidates into low-sensitivity CRM statuses. |
| `POST /extension/crm/leads/check-duplicate` | Run explicit CRM duplicate check before lead creation. |
| `POST /extension/crm/draft-leads` | Create one CRM P1 Draft Lead from browser page signals. |
| `POST /extension/crm/leads` | Create one CRM P1 Active Lead from browser page signals. |
| `POST /extension/crm/accounts/:crmAccountId/claim` | Claim one ownerless Pool Lead. |
| `GET /extension/crm/accounts/:crmAccountId` | Get extension-safe CRM account summary for display and deep link. |

P1 does not expose:

- release to Pool
- convert to Prospect Customer
- contact creation
- activity append
- source append to existing account
- screenshot upload
- AI summary
- batch import from search results

## 8. Page Context Resolve

```http
POST /extension/crm/page-context/resolve
```

Purpose:

- Resolve current browser page signals into CRM status, low-sensitivity summary, candidate hints and allowed actions.
- Support official customer website workflow.

Required action code:

- `crm.account.read`

Request:

```json
{
  "page": {
    "url": "https://www.serrano-fixtures.example/about",
    "domain": "serrano-fixtures.example",
    "title": "Serrano Fixtures - About",
    "pageKind": "OFFICIAL_SITE",
    "selectedText": "Export ceramic lighting and bathroom fittings.",
    "visibleEmails": ["imports@serrano-fixtures.example"],
    "visiblePhones": ["+1 (312) 847-1928"],
    "companyNameCandidates": ["Serrano Fixtures"],
    "socialLinks": ["https://www.linkedin.com/company/serrano-fixtures"],
    "capturedAt": "2026-06-23T00:00:00.000+08:00"
  }
}
```

Response:

```json
{
  "status": "POSSIBLE_DUPLICATE",
  "page": {
    "domain": "serrano-fixtures.example",
    "title": "Serrano Fixtures - About",
    "pageKind": "OFFICIAL_SITE"
  },
  "summary": {
    "label": "Possible duplicate",
    "displayName": "Serrano Fixtures",
    "description": "One similar Lead was found in CRM.",
    "sensitivity": "LOW"
  },
  "matchedAccount": null,
  "duplicateHints": [
    {
      "crmAccountId": "crm_9kh2",
      "displayName": "Serrano Fixtures",
      "lifecycleStage": "LEAD",
      "ownerKind": "OTHER_OWNER",
      "ownerDisplayName": "",
      "matchedFields": ["domain"],
      "confidence": "HIGH"
    }
  ],
  "allowedActions": ["CHECK_DUPLICATE", "CREATE_DRAFT_LEAD"],
  "deepLinks": {
    "tenantWebCrmAccountUrl": ""
  }
}
```

Rules:

- `matchedAccount` is populated only when current user may see an account summary.
- `duplicateHints` must be redacted according to CRM duplicate visibility and permission rules.
- `OTHER_OWNER_LEAD` and `RESTRICTED` must not leak email, phone, notes, order data, quote data, activity content or internal remarks.
- BFF may use CRM duplicate check as a read path for signals, but it must preserve CRM result semantics.

## 9. Search Results Resolve

```http
POST /extension/crm/search-results/resolve
```

Purpose:

- Resolve search result candidates into low-sensitivity CRM statuses.
- Help users avoid duplicate development from search result pages.

Required action code:

- `crm.account.read`

Request:

```json
{
  "searchEngine": "GOOGLE",
  "query": "ceramic bathroom fixtures importer Chicago",
  "capturedAt": "2026-06-23T00:00:00.000+08:00",
  "results": [
    {
      "url": "https://www.serrano-fixtures.example/about",
      "domain": "serrano-fixtures.example",
      "title": "Serrano Fixtures - About",
      "snippet": "Export ceramic lighting and bathroom fittings for hospitality projects."
    }
  ]
}
```

Response:

```json
{
  "results": [
    {
      "url": "https://www.kohler.example/",
      "domain": "kohler.example",
      "title": "Kohler",
      "status": "PROSPECT_CUSTOMER",
      "archiveReason": "NON_TARGET_ACCOUNT",
      "archivedAt": "2026-06-23T00:00:00.000+08:00",
      "summary": {
        "label": "PROSPECT_CUSTOMER",
        "displayName": "Kohler",
        "description": "CRM status is available.",
        "sensitivity": "LOW"
      },
      "matchedAccount": {
        "crmAccountId": "crm_9kh2",
        "displayName": "Kohler",
        "recordStatus": "ARCHIVED",
        "lifecycleStage": "PROSPECT_CUSTOMER",
        "ownerKind": "POOL",
        "archiveReason": "NON_TARGET_ACCOUNT",
        "archivedAt": "2026-06-23T00:00:00.000+08:00"
      },
      "allowedActions": [],
      "deepLinks": {
        "tenantWebCrmAccountUrl": "/crm/accounts/crm_9kh2"
      }
    }
  ]
}
```

Rules:

- No create, claim or mutate action is exposed from search results page P1.
- Result order should follow request order.
- For Google Search Result Page, if CRM has no visible existing object for a result, BFF omits that result from `results`; it must not return `UNKNOWN` to drive an "uncreated" tag.
- If a candidate is restricted, return `status = RESTRICTED`, low-sensitivity summary and no object identifiers unless policy allows a deep link.
- Search result tags are display-only and derived from returned fields:
  - ownership tag: `我的` / `公海` / `他人`
  - lifecycle tag: `Lead` / `PC` / `Customer`
  - archive tag: `Archived`
  - archive reason tag: `低价值` / `无效` / `非目标` / `同行` / `重复` / `不匹配` / `无响应` / `其他`
- Browser extension must not display backend raw status codes.
- Browser extension must not display combination tags such as `CRM 我的 Lead`.

## 15. Error Semantics

Stable error codes:

| Code | Meaning |
| --- | --- |
| `EXTENSION_CRM_WORKSPACE_NOT_VISIBLE` | Current session does not have `extension.crm.workspace` visible. |
| `EXTENSION_CRM_PERMISSION_DENIED` | Required action code is missing. |
| `EXTENSION_CRM_INVALID_PAGE_SIGNAL` | Page signal payload is invalid or too large. |
| `EXTENSION_CRM_DUPLICATE_BLOCKED` | CRM duplicate result blocks creation. |
| `EXTENSION_CRM_RESTRICTED_OBJECT` | Existing CRM object is restricted for current operator. |
| `EXTENSION_CRM_POOL_CLAIM_FAILED` | CRM rejected claim because object is no longer claimable or permission/resource policy denied it. |
| `EXTENSION_CRM_UPSTREAM_UNAVAILABLE` | Required downstream CRM capability is unavailable. |

Rules:

- Authorization denial must not leak restricted CRM data.
- Duplicate-blocked responses should include the CRM duplicate result if policy allows a redacted view.
- Upstream CRM errors should be mapped into stable BFF errors without losing traceability.

## 16. Tenant-Web Deep Links

P1 deep links point to tenant-web CRM detail:

```text
/crm/accounts/:crmAccountId
```

Rules:

- The extension opens tenant-web for full detail, conversion and complex editing.
- Deep links are convenience navigation, not authorization. tenant-web must still enforce its own session and route access.

## 17. Non-goals

P1 does not define:

- tenant-level plugin capability enablement.
- standalone prospecting service.
- old `/browser-prospecting/*` endpoints.
- release to Pool.
- convert to Prospect Customer inside plugin.
- contact creation.
- activity append.
- source append to existing CRM account.
- screenshot upload.
- AI-generated summary or decision.
- search-result batch import.
